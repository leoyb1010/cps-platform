> 后端 154 e2e + 全部单测通过、`nest build` 通过;前端 45 单测 + `vite build` 通过。每项均带 file:line 证据与回归测试或验证。

### P0 —— 商业化阻断(4 项)

| # | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| P0-1 | **限流全局塌陷 + 审计 IP 失真**:未设 `trust proxy`,nginx 反代后 `req.ip` 恒为 nginx 容器 IP → 登录 10/min、改密 5/min、全局 120/min 全变成「全平台共享一个桶」,任意一人打满即锁死所有账户登录;审计与 refreshToken.ip 全记 nginx IP | `main.ts`(无 trust proxy)+ `nginx.conf:63-64`(注入 XFF)+ `app.module.ts:62`(throttler 默认按 req.ip) | `main.ts` 设 `trust proxy`(env `TRUST_PROXY_HOPS` 默认信任 1 跳 nginx),限流恢复按真实客户端 IP |
| P0-2 | **合约目标金额单位错位**:`targetGmv` 属整数分字段(seed 按分存、fulfillment 用订单分对比),但两个创建端点直接存 dto(元),漏 `fromYuan()` → 合约成交到目标的 **1%** 就自动判定达标进结算态 | `portal.controller.ts:555`、`business.controller.ts:790`(同行 firstPrice/myQuota 都转了) | 两处补 `fromYuan()`,与 seed / 拦截逻辑同域 |

| P0-4 | **审计日志越区读**:`/audit-logs` 只按 category 过滤、无 scope 收窄,`brandaudit`(audit 角色 + brand scope)可读**全平台**跨租户结算/提现/冲账金额与 before/after JSON | `audit.controller.ts:14`、`audit.service.ts:99-105` | 审计表无租户维度、无法按品牌切分 → controller 加 `assertPlatform`,非平台账户零可见 + 新增 e2e 回归 |

### P1 —— 资金正确性与越权(3 项)

| # | 缺陷 | 证据 | 修复 |
|---|---|---|---|
| P1-1 | **准备金逆向追偿跨代理错配(静默资损、对账全绿)**:一张结算单聚合多代理订单时,`clawback` 只按 settlementId 取「最早到期」释放行、缺 agentId → 退款代理 A 现金不足时,可能拿代理 B 的准备金抵 A 的退款,B 永久少拿;现金侧按 agentId 精确,追偿侧不认 → 口径不一致,结算单级恒等式仍成立、告警不触发 | `reserve-release.service.ts:80` + 三处调用不传 agentId | `clawback` 加 agentId 精确过滤,三处调用传退款订单 agentId + **新增多代理隔离回归测试**(代理 Y 到期更早也不被误吃) |
| P1-2 | **合约商品归属未校验**:`proposeContract` 直接存 `dto.productId`,品牌可发起引用他方商品的合约,fulfillment 按 productId 匹配时可能错配到他方履约链路 | `portal.controller.ts:555`(proposeBarter/createClaim 都校验了,唯此漏) | 提供 productId 时校验 `product.brandId === 调用方品牌`,否则 403 |
| P1-3 | **CPS 退款幂等键未绑内容**:合作方自带 `Idempotency-Key` 复用到不同交易号(extOrderNo)会命中首笔结果直接回放 → 第二笔实际没退却返回成功(终端用户漏收退款) | `cps.service.ts:175` | 幂等键始终纳入 extOrderNo:同笔退款回放、不同交易号各自执行 |

## 四、商业化优化计划

### P0 —— 上线前必修(收敛到 1 项)

| 项 | 证据 | 动作 | 工作量 |
|---|---|---|---|
| **PostgreSQL 金额列 int4 溢出** | `schema.postgres.prisma` 金额列为 `Int`(int4),整数分后上限仅 ¥21,474,836.47;`OrderIngestDto.amount` 无 `@Max` | 金额列改 `@db.BigInt`(两份 schema 同步)+ DTO 加 `@Max`;需 PG 环境回归(CI 用 SQLite 撞不到) | 1–1.5d |

### P1 —— 上线前应做(体验/健壮)

| 项 | 证据 | 动作 |
|---|---|---|
| 门户查询无分页上限 | `portal.controller.ts:167` 代理首页把全部历史订单 `findMany` 进内存做趋势 | 加时间下界(默认近 N 天)或游标分页,高频代理防内存爆 |
| 退款并发第二笔以 500 结束 | 三条 refund 的 `order.create` 未捕获 P2002(ingest 有优雅处理) | 比照 ingest 捕获 P2002 → 返回幂等式「已退款」(核心不双退已由唯一约束保证,仅形态优化) |
| 演示模式内部写操作失败 | `Contracts.tsx:172`/`Barter.tsx:121`/`Products.tsx:44` 直连后端,mock 无兜底 | 参照 `MemberModals`/`Complaints` 的 `isRealApi` 分流,给演示模式加本地 store 兜底,兑现「三入口演示全可体验」承诺 |
| 入驻→首单动线断点 | 向导提交后仅 toast、无「开门户→上架→接回传」指引 | 入驻状态卡改 checklist,每步带跳转按钮 |

### P2 —— 上线后迭代(加固)

- **AIGC 反代租户隔离 fail-closed**:未配 `AIGC_INTERNAL_SECRET` 时下游租户塌缩到同一 default 工作区,建议生产启动强制断言(`aigc.controller.ts:99`)
- **CPS orderQuery nonce 防重放**:只读查询在 120s 窗内可重放,建议对齐写接口加 nonce(`youdao.controller.ts:137`)
- **RSA 私钥前端本地生成**:当前服务端 keygen 违背「私钥自留」信任模型,改为前端 WebCrypto 生成 + 只上传公钥(`portal.controller.ts:440`)
- **`/metrics` token 常量时间比较** + 移除 query 串接收(`health.controller.ts:56`)
- **成员 account 规范化**:大小写/空格/同形字查重(`members.controller.ts:24`)
- **real 模式素材台完整空态**:Aigc 素材列表本体(非仅 KPI)在 real 模式改真实生成流展示或空态
