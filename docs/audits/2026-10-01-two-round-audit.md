## Round 2 independent challenges and repairs

1. **Cross-session responses and mutation retries.** A delayed successful200 response from an old account remained readable after logout and a new login. A refresh could also complete before a principal switch and replay the original operation as the new principal. Request generation is now checked after response arrival, refresh, retry and JSON decoding. Internal same-principal token rotation does not change the principal epoch. Five HTTP regressions cover outage, delayed refresh, late200 body and switch-before-retry paths.
2. **Rendering failure charged as success.** Carousel/video rendering exceptions were caught and returned as completed jobs with null assets. Exceptions and empty outputs now fail the job, release its own reservation, charge zero and expose no raw renderer exception. Four real SQLite billing regressions cover thrown and empty rendering results.
3. **Legacy Studio routes were not tenant-scoped.** Configured gateway mode now exposes only explicitly workspace-aware factory/billing families. Single-user automation/settings routes are403 in that mode. Unsigned nonproduction demo routes require a loopback Host and, when present, a loopback Origin. API body size is bounded at2MiB. Three Hono request-boundary tests verify this contract.
4. **Signed identity normalization could collapse distinct imported IDs.** HMAC verification was followed by lowercase/replacement/truncation. Initial rejection-only hardening broke actual seed agent A-2041 and user U-007; independent review caught it before publication. The final decoder preserves the established agent-A-<digits> and U-<hex> namespaces and their historical lowercase storage keys, reserves their lowercase wire aliases, and rejects other lossy transformations. A real gateway-to-decoder contract test uses the seed agent, brand and platform users. Imported noncanonical IDs still need an explicit mapping decision before future release; no data was silently moved.
5. **Render filesystem and network boundary.** Dot-directory identifiers are rejected, output segments bounded, factory artifacts use unique job IDs rather than shared content IDs. The built-in renderer uses an opaque-origin document, restrictive CSP, and browser-context request/WebSocket denial and service-worker blocking; it accepts self-contained data/blob assets only. Unit tests verify routing/CSP/path policy. A hosted real-Chromium regression uses only a disposable localhost canary to challenge popup first navigation, iframe, image, stylesheet, fetch, beacon and WebSocket paths; it must observe zero canary requests. This closes the independent review finding that page-only routing does not intercept a popup's first navigation. Remote fonts now fall back to local fonts. Optional Hyperframes producer rendering is a separate path and is not claimed to have the same verified sandbox; do not enable it on untrusted generated HTML without dedicated process/egress isolation.
6. **Password/session write races.** Password changes, token-generation increments and refresh revocation now commit atomically. Refresh records carry their validated user tokenVersion. Issuance and rotation lock/CAS the same user row so an old validated password cannot gain the new generation; access JWTs retain that validated generation. Delayed logout revokes the old generation including rotation children, without invalidating a newly logged-in generation. Real disposable SQLite tests cover rollback on injected revocation failure, old validation after password change, concurrent change/rotate, delayed logout, and actual old-table migration backfill. The auth suite contains12 tests.
7. **Dependency and verification upgrades.** Required compatible dependency/lockfile repairs remove known advisories. Vitest4.1.11 was necessary because no patched3.x existed for the affected advisory; Hyperframes0.7.43 removes vulnerable browser/archive dependencies; esbuild0.28.1 overrides the remaining Windows-dev-server low advisory. Hyperframes export signatures were inspected and job construction exercised. All three npm audits reported0 at the local checkpoint. No arbitrary product version bump was made.

## Actual browser follow-up

The first hosted run passed the portal browser journeys and produced10 desktop/tablet/mobile captures. Inspection found that SVG date labels were horizontally squeezed in narrow brand/agent cards. AreaLine now renders four date ticks in an unscaled12px HTML layer while preserving plotted data and geometry. Component tests cover short/empty series and tick counts; browser checks measure the real font and page overflow. Dashboard captures were taken mid-entry-animation, so final evidence uses reduced-motion and disabled screenshot animations rather than changing the product animation. All final gates run again on the follow-up commit. Studio captures also exposed two text fields missing explicit type attributes, leaving18px browser-default controls because the stylesheet targets input[type=text]. Both fields now use the existing form styling; mobile factory text/select controls are44px with16px text. Hosted UI checks measure their sizes, capture scrolled form content, and exercise empty validation, disabled loading actions, a synthetic503 and a successful local-copy retry. Inspection of that failure state also revealed the shared success-check icon on error messages. Notifications now take an explicit success/error variant; failure call sites were audited, errors use an alert icon/color and live-region role, and an older timeout cannot erase a newer notification. Default one-argument successful notifications remain compatible.

## Release and rollback boundaries

Fetch only the dedicated repair branch for review. Do not merge or deploy without a separate release decision. Back up both core and Studio databases. Drain in-flight generation before introducing the reservation-state schema; inspect legacy reserved balances rather than guessing or retroactively rewriting financial ledgers. Apply the additive RefreshToken.tokenVersion migration before running this code. It backfills existing rows from their user generation. Logout remains account-generation-based, so other sessions in that old generation must log in again.

A source rollback does not authorize deleting migration columns, reservation state or ledger rows. Reverting to old authentication code can make refresh tokens unusable for nonzero-generation accounts and reintroduces the fixed race; plan controlled re-login rather than destructive schema rollback. Restore production data only through a separately rehearsed, approved recovery procedure. No real restore was performed here.

Residual limits: mocked portal UI is not live backend UX; real providers, external callbacks, DNS rebinding at deployment egress, payment/Youdao production integration, optional Hyperframes runtime and production load were not tested. Browser sandboxing does not replace OS-level resource/egress limits. Earlier NODE_ENV=test builds emitted bundle warnings; actual production builds measured web482KB and Studio376KB for the main bundles, below the default500KB warning threshold. Factory image/video provider adapters remain documented MVP behaviors, not proof of real AI image/video generation. A finite audit cannot certify zero bugs or flawless accessibility.
